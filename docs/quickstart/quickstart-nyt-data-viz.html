Open Design · Quickstart · The Upshot Edition

From one sentence to a working prototype.

Open Design drives the coding agent already on your machine — Claude Code, Codex, Gemini, and a dozen more — and turns a single prompt into a live, sandboxed design you can save to disk.

How to read this: eight panels, each a step. Local-first · no cloud account required · runs on pnpm tools-dev. — Source: QUICKSTART.md, Open Design v0.10

01 · The loop

Every design is the same five-beat motion.

You type. An agent streams. The app reads one <artifact> tag out of the stream and renders it live. Then you save.

Beat 1
Prompt
Pick a skill + a design system, type what you want, hit Send.
Beat 2
Agent
Your local CLI (or a BYOK API) streams tokens into the left pane.
Beat 3
Parse
The streaming parser pulls the <artifact> out as it arrives.
Beat 4
Render
HTML paints live in a sandboxed iframe on the right.
Beat 5
Save
“Save to disk” writes .od/artifacts/<ts>-<slug>/index.html.

Same parser, same iframe, every time — only the transport upstream of it changes (panel 06).

03 · Before you start

Three numbers and an option.

WhatVersionNotes
Node.js~24 (24.x)Enforced by package.json#engines. Node 22 is not supported.
pnpm10.33.2Pinned via packageManager; let corepack select it.
OSmacOS · Linux · WSL2Primary paths. Windows native is best-effort.
Agent CLIoptionalClaude Code, Codex, Gemini, OpenCode, Cursor Agent, Qwen, Devin, Copilot… or none → use BYOK API mode.

If the daemon can’t see a CLI you installed, its directory isn’t on the PATH of the process running the daemon. Fix the PATH, then hit Rescan in Settings → Execution mode.

04 · Get it running

Pick a lane. Two commands either way.

Dev mode — daemon + web in the foreground.

# from the repo root
corepack enable
pnpm install
pnpm tools-dev run web
# open the URL tools-dev prints

Full desktop — daemon + web + Electron in the background.

pnpm tools-dev

Docker — no local Node or pnpm.

cd deploy
cp .env.example .env
openssl rand -hex 32   # paste into OD_API_TOKEN
docker compose up -d
# http://localhost:7456

One rule: pnpm tools-dev is the only lifecycle entry point. The legacy pnpm dev / pnpm start aliases were removed on purpose.

05 · Your first design

Type a prompt. Watch it build itself.

  1. On first load the app auto-detects your agent CLI and defaults to the web-prototype skill + the Neutral Modern design system.
  2. In the top bar, choose a Skill (grouped Prototype · Deck · Template · Design-system) and a Design system to set the visual language.
  3. Type a prompt — e.g. “a pricing page for a calm habit-tracker” — and hit Send.
  4. The agent streams into the left pane; the parsed artifact renders live in the sandboxed preview on the right.
  5. When it settles, click Save to disk to persist it under ./.od/artifacts/.

Behind every Send, the system prompt is composed in three layers: BASE_SYSTEM_PROMPT + the active design system (DESIGN.md) + the active skill (SKILL.md). Swap either in the top bar and the next send uses the new stack.

06 · Two ways to reach a model

Local CLI by default; an API key as the fallback.

The hero path is the one Open Design picks for you when it finds an agent. Both feed the identical artifact parser and the identical sandboxed iframe.

ModeWhenHow a request flows
Local CLIdefault — a CLI was detectedfrontend → daemon /api/chat → spawn(<agent>) → stdout → SSE → artifact → preview
API (BYOK)no CLI, or you prefer itfrontend → daemon /api/proxy/{provider}/stream → normalized SSE → artifact → preview

Providers in API mode: Anthropic · OpenAI · Azure OpenAI · Google Gemini. The only real difference is transport — local CLIs fold the system prompt into the user message because they have no separate system channel.

07 · Keep this nearby

The everyday commands.

pnpm tools-dev            # all 3, background
pnpm tools-dev run web    # daemon+web, foreground
pnpm tools-dev status     # inspect runtimes
pnpm tools-dev logs       # tail logs
pnpm tools-dev check      # status + logs + dx
pnpm tools-dev stop       # stop everything
pnpm guard                # repo-level checks
pnpm typecheck            # workspace types
# data lives under .od/ (gitignored)
#   app.sqlite  · projects/conversations
#   artifacts/  · saved renders
#   projects/<id>/ · per-project cwd

Stuck? “No agents found” → install a CLI or switch to API mode. “Artifact never renders” → the model didn’t wrap output in <artifact>; try a stricter skill or stronger model. Go deeper: architecture.md · skills-protocol.md · agent-adapters.md · modes.md · roadmap.md
